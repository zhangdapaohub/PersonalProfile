# 提问库设计大纲（Question Bank）

> 状态：**待确认**——大纲经确认后再实现。
> 目标：一套能把一个人「从里到外、从自身到所拥有的一切」解析干净的提问库，
> 树状维度逐层划分，每个指标（叶子）挂若干提问，问答结果按路径写入档案快照。

## 1. 核心设计原则

1. **路径同构**：提问库的树 = 档案的维度树（dimensions.json 同构）。
   一个提问的答案最终落到一个 `path`（如 `body.health.sleep_hours`），
   与现有 store 的 overrides 无缝对接，**不改数据模型**。
2. **三层结构**：`领域（大节点）→ 维度（分组）→ 指标（叶子）`，提问挂在指标上。
3. **一个指标，多个提问**：
   - 主问（直接获取）
   - 追问 probe（沿答案深挖，如"为什么""举例子""和上次比呢"）
   - 校验问（交叉验证，如体重既自述又见体检报告）
4. **三种提问类型 type**：
   - `fact` 事实型：可量化、可佐证（身高、存款、职位）
   - `story` 叙述型：经历与原因（"讲一次你搬家的经历"）
   - `eval` 评价型：主观自评/他评（"你给自己的耐心打几分"）
5. **双视角 perspective**：`self` 自述 / `other` 他评（"你觉得朋友会怎么形容你"）。
   同一指标可同时收两个视角，差异本身是档案信息。
6. **四级完整度 completeness**：`未知 → 粗略（自述）→ 精确（数值）→ 佐证（有材料）`。
   每个答案可附 evidence（体检报告、照片、账单、聊天记录摘录）。
7. **时间轴联动**：时间敏感指标（体重、职位、居住地）每次采集写入**新快照**；
   稳定指标（出生日期）写入根态。是否"敏感"在指标上标记 `volatile: true`。

## 2. 模块定位与指标预命名（v2 修订，采纳用户意见）

### 3.1 提问库是独立模块，与展示模块分离

```
personal_profile/
├─ assets/
│  ├─ dimensions.json      # 指标注册表：全部指标的 path + 中文名 + 单位（预先命名好）
│  └─ question_bank.json   # 提问库：挂在注册表指标上的问题集（本模块数据）
├─ core/qbank.py           # 题库模块逻辑：加载/校验 maps_to/进度推导/答案落库
├─ web/                    # 展示模块（已有）：时间轴/详情，不感知提问库
└─ cli/                    # ask 子命令（P3）
```

- **展示模块（时间轴/详情/连线）与提问库互不感知**：展示只消费 archive；
  提问库只通过现有写入 API 落数据。问答面板是 web 里的一个独立入口。
- **CLI 与 Web 共用 qbank 模块**，题库逻辑只写一份。

### 3.2 指标预先命名：注册表唯一，题库只引用不造名

- **指标的 path / 中文名 / 单位 全部预先定义在 dimensions.json（指标注册表）**，
  题库中每题 `maps_to` 指向注册表现有 path；要新增指标，先注册再挂题。
- 收益 1：答案落库时 name/unit 自动带出，答题界面不出现任何"起名"环节。
- 收益 2：**进度无需单独存储**——某指标已答 = 该快照 overrides 存在此 path，
  提问库进度 = 题库 path 集合 ∖ 快照 overrides 键集合，纯推导、零状态。

### 3.3 直接答题转入快照

- 每题提交即 `set_value(maps_to, value)` 写入当前快照（沿用现有
  `POST /api/value`，零新写路径）；
- `volatile` 指标（体重/职位/居住地）提交前提示「为本次采集新建时间态？」，
  确认则新快照（自动继承上一个）再写入；
- story 叙述题：全文作为该指标 value 落库；probe 追问答案落子指标
  （如 `mind.desire.fears.origin`）；二期 AI 抽取可再把叙述拆成 fact 落到注册表其他指标。

## 4. 各领域树状明细（含示例提问）

### 3.1 identity 身份与存在
```
identity
├─ basic 基本信息：姓名/曾用名/昵称、生日、出生地、现居地、民族、血型、生肖星座
├─ legal 法律身份：身份证/护照、户籍、婚姻状况、兵役
├─ origin 出身溯源：籍贯、家族姓氏渊源、出生故事（父母视角）、名字由来★
└─ tags 一句话身份：自我介绍、三个标签词、别人眼中的第一印象
```
示例：
- 名字由来（story）：「你的名字是谁起的？有什么含义或故事？」
- 现居地（fact, volatile）：「你现在住在哪？（城市+居住形态：自有/租房/与家人）」

### 3.2 body 身体（从里到外的物理层）
```
body
├─ appearance 外貌体征：身高/体重/鞋码、体型自述、五官特征、发型、
│   穿搭风格（与 lifestyle 交叉引用）、声音特征、惯用手
├─ health 健康：病史/手术史/过敏源/慢性病、家族遗传史、疫苗、
│   用药清单、心理就诊史
│   ├─ sleep 睡眠：入睡时间/时长/质量自评、梦（常梦主题）
│   └─ energy 精力：精力曲线（晨型/夜型）、易疲劳点、恢复方式
├─ medical 医疗检测：inbody 体成分（已接入）、血压/血糖/血脂、
│   视力听力牙、体检异常项与复查计划
└─ senses 感官与体感：五感敏锐度、疼痛耐受、天气敏感、晕车等
```
示例：
- 精力曲线（fact+eval）：「一天中你状态最好的时段是？早上起来多久才'清醒'？」
- 体检异常项（fact, evidence）：「最近一次体检有哪些异常/复查项？报告还在吗？」

### 3.3 mind 心理与内在
```
mind
├─ personality 性格：大五维度逐项（外向性/尽责性/宜人性/情绪稳定性/开放性
│   各 3 问）、MBTI/星座自述与认同度、优缺点自评、他评反差
├─ values 价值观：金钱观、是非底线、公平感、家庭与事业排序、
│   最不能容忍的事、敬佩谁及为什么★
├─ emotion 情绪：主情绪基调、生气/悲伤/开心时的外在表现、
│   压力反应模式（战/逃/僵）、恢复方法、情绪史上关键事件
├─ belief 信念：世界观（人性本善/恶？世界公平吗？）、宗教/哲学倾向、
│   人生信条、对死亡的态度
├─ desire 欲望与恐惧：最渴望的 3 件事、最深的恐惧、经常焦虑什么、
│   主动回避什么、深夜emo的源头
└─ cognition 认知：思维风格（具象/抽象）、学习方式（看/听/做）、
    决策风格（理性/直觉）、注意力与记忆特点、自我觉察盲区
```
示例：
- 压力反应（story）：「上次你压力大到失控是什么时候？当时身体/行为有什么反应？」
- 他评反差（eval, other）：「你觉得最了解你的人会用哪三个词形容你？你希望是哪三个？」

### 3.4 capability 能力与知识
```
capability
├─ skills 技能：硬技能清单（+熟练度1-5+佐证）、软技能、
│   语言能力、动手能力、在学技能
├─ education 教育经历：学历时间线、专业与原因、成绩自评、
│   重要老师、校园角色
├─ knowledge 知识结构：专业领域、业余专长（能讲半小时的话题）、
│   信息茧房自评
├─ expression 表达：口头禅、说话风格（直/绕）、书面能力、公开表达经历
└─ habits 习惯：每日例行、小动作癖好、拖延模式、自律自评
```
示例：
- 硬技能（fact）：「列出你能拿出去换钱的技能，各打几分（1-5）？有证书/作品佐证吗？」

### 3.5 relations 关系网络
```
relations
├─ family 家庭：父母（各自性格/关系亲疏/影响最深的话）、
│   兄弟姐妹、配偶/伴侣（相识故事★）、子女、祖辈、其他亲戚
├─ social 社交：挚友名单（+相识原因）、朋友分层、社交风格（独处/聚会）、
│   对手/讨厌的人及原因、恩人、渐行渐远的人
├─ org 组织：公司/团队/职务、直属上下级关系、师徒、行业圈子
└─ pets 宠物与其他：宠物、长期线上关系（网友）、单向崇拜对象
```
- 重要他人（父母/配偶/挚友）支持 **递归子档案**：对方也建 Person，
  在本侧记 `relations.family.father → person_id`，实现"关系也是档案"。
示例：
- 父亲（story+eval）：「用三个词形容你父亲？哪件事最能代表他？你们多久联系一次？」

### 3.6 experiences 经历与时间（与快照时间轴天然契合）
```
experiences
├─ timeline 大事记：逐年/逐阶段事件（升学、搬家、工作变动、
│   疾病、获奖、事故、告别）——每条 = 一个候选快照
├─ stages 阶段画像：童年/小学/中学/大学/职场各阶段的
│   生活状态、圈子、当时在乎什么、现在的评价
├─ peaks 高光与遗憾：最自豪 3 件事、最后悔 3 件事、转折点★、
│   如果重来会改什么
└─ daily-life 生活变迁：住过的所有地方、用过的昵称网名、
    阶段性消费水平变化
```
示例：
- 转折点（story）：「哪件事之后你'变了个人'？变前的你 vs 变后的你各什么样？」
  （答案直接支撑「断裂/主动重塑」链接的建立）

### 3.7 possessions 拥有物（这个人所拥有的一切）
```
possessions
├─ assets 资产：房产（套数/地点/来源）、车辆、存款/投资/理财、
│   股权/副业收入、负债（房贷/借款）、保险配置
├─ items 物品：常用贴身物、最贵物品、最有感情物品★、收藏、宠物
├─ digital 数字资产：常用账号平台、订阅服务、游戏资产、
│   相册数据、创作的账号与内容
└─ ip 作品与权利：文章/代码/作品署名、专利、商标、
    署名的项目、可传承的东西
```
示例：
- 最有感情物品（story）：「如果家里只能抢救一件东西，你拿什么？它是什么来历？」

### 3.8 lifestyle 生活方式
```
lifestyle
├─ diet 饮食：口味偏好/忌口、一日几餐、外卖/做饭比例、咖啡因酒精、减肥史
├─ clothing 穿着：风格、买衣渠道与频率、鞋包偏好、护肤化妆
├─ housing 居住：户型与整洁度自评、装修风格、理想住所、家务分工
├─ transport 出行：通勤方式、驾龄车技、旅行频率与偏好类型
├─ entertainment 娱乐：常刷的APP/时长、追剧游戏音乐、运动频率与项目、
│   兴趣爱好（+投入度）
└─ spending 消费：月均支出结构、冲动消费点、省钱与大方并存处、记账习惯
```
示例：
- 消费结构（fact, evidence）：「上个月大概花了多少？大头是哪三项？」（可看账单佐证）

### 3.9 attention 时间与注意力
```
attention
├─ time-allocation 时间分配：典型工作日/休息日24h去向、
│   最想收回的时间黑洞
├─ information 信息源：常看的媒体/博主/播客、行业信息渠道、
│   已屏蔽的信息类型
└─ current-focus 当前关注：最近在研究什么、正在读的书、
    正在解决的最大问题
```
示例：
- 时间黑洞（eval）：「如果把上周的时间拍成慢放，哪一段你最想快进？为什么？」

### 3.10 future 意向与未来
```
future
├─ goals 目标：1年/3年/10年目标、今年必须完成的一件事
├─ plans 计划：已排期的计划、买房/结婚/生育/移民等人生节点计划
├─ worries 担忧：对健康/财务/家庭/职业的具体担忧、最坏设想
├─ bottom-line 底线：绝不做的事、绝不放弃的东西、
│   崩溃前最后的支撑
└─ legacy 终局：想被记住成什么样、遗愿、给十年后自己的话★
```
示例：
- 给未来自己（story）：「写一句话给 40 岁的自己，你会写什么？」

## 5. 提问条目的元数据结构（实现时的 JSON 形态）

```json
{
  "id": "q_mind_desire_fear_01",
  "maps_to": "mind.desire.fears",
  "type": "story",
  "perspective": "self",
  "question": "你最深的恐惧是什么？它最早出现在什么时候？",
  "probe": ["这个恐惧影响过你的哪个决定？", "身边的人知道吗？"],
  "completeness": ["粗略", "精确", "佐证"],
  "volatile": false,
  "recurrence": "年度复访"
}
```

- `maps_to` 即档案 path；答案值 + unit/name 走现有 `POST /api/value`。
- `probe` 生成的追问答案同样落 path（可带子段，如 `mind.desire.fears.origin`）。
- 复访类指标（`recurrence`）可生成周期性采集任务（后续可接自动化）。

## 6. 采集机制设计

1. **问卷模式**：Web 端新增「提问」面板——按树展示进度（每领域完成度%），
   一次只出 1 题，答完自动推进；支持跳过/稍后。
2. **落库时机**：每次提交即写入当前选中快照；`volatile` 指标提示「是否为新时间态采集」。
3. **渐进解析**：完整度四级让"没答完"也有效——树状面板直观显示哪些分支还是未知。
4. **AI 追问（二期）**：接入大模型后按 probe 自动追问，从自由叙述中抽取 fact 答案。
5. **导入兼容**：体检报告等结构化材料直接走现有 API 批量写入（如 InBody 先例）。

## 7. 形式推荐

### 6.1 存储形式：单文件 JSON（推荐）✚ 同构嵌套

| 方案 | 评价 |
|---|---|
| **单文件 `question_bank.json`，按维度树嵌套** | ✅ 推荐。与 dimensions.json 同构，加载一次全局可用；~600 题估计 400KB 内，无性能问题；树状结构即目录，好审阅好维护 |
| 按领域拆 10 个文件 | 可选优化，题量涨到上千再拆不迟（P1 先单文件） |
| SQLite / 数据库 | ❌ 过度设计：无关联查询需求，违反零依赖原则 |
| 代码内嵌字典 | ❌ 不可直接被 AI/工具批量消费，改题要动代码 |

嵌套形态：题挂在指标（叶子）节点内，运行时按需展平：
```json
{ "key": "mind", "name": "心理与内在", "children": [{
    "key": "desire", "name": "欲望与恐惧", "children": [{
      "key": "fears", "name": "最深的恐惧", "volatile": false,
      "questions": [{ "id": "q_...", "type": "story", "text": "...", "probe": ["..."] }]
    }]
}]}
```

### 6.2 采集呈现形式：一次一题 + 树状进度为主，三条旁路

600+ 题不可能一次填完，**核心是"随时停、随时续、看得到进度"**：

| 模式 | 用途 | 阶段 |
|---|---|---|
| **① 逐题对话式（主）** | 一屏一题，按 type 渲染控件（fact→数值/日期/选项，story→多行文本，eval→滑杆/星级），答完自动推进；左栏树状进度（领域完成度%），自动记断点 | P2 |
| **② 场次制 session** | 每场 20~30 题 / 10-15 分钟，凑一场算一场，防劝退 | P2 |
| **③ 材料导入式** | 体检报告/简历等结构化材料直接批量写 path（InBody 先例） | 已有 |
| **④ 自由叙述 + AI 抽取** | 讲一段话，AI 抽出多个指标答案与 probe 追问 | P4 |

### 6.3 优先级分级（强烈建议）

600 题全答不现实，题分三级：
- **P0 核心题 ~80 题**：最简画像，约 30-40 分钟答完，覆盖全部 10 领域
- **P1 完整题 ~250 题**：常规采集
- **P2 深挖题 ~270 题**：含 probe 深挖、他评视角、复访题

第一遍只走 P0 → 立即得到一个"70 分档案"，P1/P2 按兴趣补。`priority` 加入题目元数据。

### 6.4 其他形式要点

- 答案控件随 type 变化，**不让用户面对 600 个文本框**
- 每个 session 结束出小结：「本场新增 12 项 / 触发 1 个新时间态建议」
- `recurrence` 复访题（体重、职位）可接自动化定时提醒

## 8. 实现拆步（确认后执行）

| 阶段 | 内容 | 产物 |
